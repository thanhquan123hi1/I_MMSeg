# I-MMSeg versus M2-Plus: fixed train304/test76 protocol

This adaptation retrains I-MMSeg with the same data, SCAR augmentation, epoch
budget and evaluation protocol as M2-Plus, preserving I-MMSeg's architecture and
original objective. It is not an exact reproduction of the paper's training
recipe, and different losses/pretraining/LRs must be disclosed in the comparison.

Training protocol: `myops380_train304_test76_last_v1`.
Metric protocol: `myops380_voxel_v3`, distances in voxels, **not mm**.

## Data and frozen reference

`benchmark/reference/splits` contains the original 1,972 slice IDs from 304 train
patients and the 76 test IDs. Their sets match both upstream I-MMSeg `list/` and
local SCAR `preprocessing/splits/myops380_no_val/`. No split is regenerated by seed.
No validation dataset/loader, best-checkpoint selection or early stopping exists
in the new training path. Old validation-volume caches are ignored.

Expected normalized cache structure:

```text
Processed_data/
  bSSFP/{train_npz/<slice>.npz,test_vol_h5/<case>.npy.h5}
  LGE/{train_npz/<slice>.npz,test_vol_h5/<case>.npy.h5}
  T2w/{train_npz/<slice>.npz,test_vol_h5/<case>.npy.h5}
```

Each modality file must contain aligned `image` and `label` arrays. Images must
already be finite floats in [0,1]. This reader does not repeat division by 255.
Targets must have integer values 0..3. Source label order is explicit and checked
against metadata when available. Volumes use HWD axis order.

SCAR sources/configs, its commit and dirty working-tree state are snapshotted in
`benchmark/reference/scar/` and `manifest.json`; no live SCAR installation is
required. `scar_augmentation.py` extracts its augmentation definitions verbatim;
`scar_metrics.py` is a byte-identical copy of its metric source. Only the
MyoPS380 `dataset_rows` / `summarize_dataset_rows` path is used. SCAR is not edited.

## Model, labels and objective

Architecture is the original `VisionTransformer` implementation, three modality
inputs, 128x128, four output classes, n_skip=3. Only four device-loading lines in
`networks/vit_seg_modeling.py` change: embeddings load on CPU and move to the
input device instead of hardcoding CUDA. Parameters, heads and math are unchanged.

Internally **legacy** means 0 background, 1 normal myocardium, 2 scar, 3 edema.
SCAR **canonical** means 0 background, 1 normal myocardium, 2 edema, 3 scar.

- Legacy cache -> legacy train target, no swap.
- Canonical cache -> legacy train target, swap 2/3 once at the train boundary.
- Legacy model argmax -> canonical prediction, swap 2/3 once at export.
- Test GT -> canonical, using its declared source order. Predictions and GT are
  therefore compared in the same canonical space without changing model heads.

`benchmark/objective.py` uses unchanged `utils.DiceLoss` and `ContrastiveLoss`.
`trainer.py` and the original entry points are retained as reference. The loss is:

- Main: 0.2 CE + 0.8 original Dice.
- Decoder: sum of the three decoder losses, each 0.2 CE + 0.8 Dice.
- Original Dice: batch/spatial reduction, squared denominator, smooth=1e-5,
  class weights [0.5,1,1,1], divided by four.
- Original contrastive sampling/temperature, ignores `([2,3],[0],[0])`,
  sample_num=10, average over modalities, weight=0.1.
- Contrast enabled exactly when zero-based epoch index > 20.
- Before index 100: decoder + 0.1 contrast.
- From index 100: main + 0.5 decoder + 0.05 contrast.

**Two-GPU text-anchor adapter:** upstream train.py defaults to DataParallel on
two GPUs. Each replica returns four class anchors, gathered to eight anchors;
the unchanged contrastive loss hardcodes `prompt_num=2`. This single-device
pipeline explicitly repeats the four text anchors twice before that loss. It
preserves the original two-GPU text-anchor multiplicity and avoids the otherwise
invalid single-device 4-anchor/8-label shape. It does not change the loss
implementation. Regression tests compare values AND gradients against the actual
archived trainer block at indices 0,20,21,99,100,299.

## Initialization and resources

Use Python 3.11 or newer (the cache fingerprint code uses `hashlib.file_digest`).

```powershell
python -m pip install -r requirements-benchmark.txt
```

Install the desired PyTorch CUDA build for the training machine first. This
portable requirements file avoids upstream requirements.txt's machine-specific
Conda paths. CLIP/open_clip are not needed when using the supplied text embeddings.

Without `--pretrained`, encoders are RANDOM, matching what the original entry
point actually executes (its `_pretrain` directory label never loaded weights).
Both supplied `text_features/*.pth` embeddings are always loaded and fingerprinted.
No segmentation checkpoint is used for initialization.

For encoder pretraining, explicitly pass `--pretrained /path/R50-ViT-B_16.npz`.
The adapter validates and loads compatible root/body ResNet weights into all
three actual encoders. The old `VisionTransformer.load_from` addresses ViT
modules that are absent from this model, so it is not called. Extra NPZ ViT
weights are unused. Initialization choice/hash is recorded; make a deliberate
choice consistently with M2-Plus before final runs. Full external NPZ loading
has not been verified here because that file was not supplied to this adaptation.

Default batch is TOTAL physical batch 16 on one device, accumulation 1. It is not
multiplied by GPU count. This batch has not been VRAM-tested on the local GPU.
Original batch Dice, contrastive interactions and BatchNorm make accumulation
different from a large physical batch. If memory requires a smaller microbatch,
lock it before the final run and disclose it. No loss/reduction is rewritten to
force equivalence. Default FP32 preserves original numerical precision; optional
Optional BF16 AMP is explicit and recorded, with the unchanged objective computed
in FP32. **FP16 is rejected:** GPU audit reproduced NaNs inside the original
cosine attention before loss evaluation. FP32 remains the default. AdamW uses the original all-parameter
weight decay 1e-4, default LR 0.001. This differs from SCAR's grouped decay.
Gradient norm is clipped at 1.0. Polynomial LR power 0.9 advances after successful
optimizer updates only, with skipped AMP steps tracked. The new scheduler fixes
the old entry point's update offset to use the shared step-level convention.

## Train and resume

Run from the I_MMSeg root. Example using the available normalized legacy cache:

```powershell
python train.py --data-root E:/STUDY/DATASET/MyoPS380/Processed_data --label-order legacy --output-dir outputs/im_mseg_seed1234 --batch-size 16 --accum-steps 1 --base-lr 0.001 --seed 1234 --device cuda:0
```

The pinned manifest directory is the default. To use the SCAR version explicitly,
add `--list-dir D:/NCKH/SCAR/preprocessing/splits/myops380_no_val` from the outset.
The exact same manifest bytes must be used on resume.

For multiple sessions, add `--epochs-per-run 50` to the first command. The
planned budget stays 300. Continue with the same settings, for example:

```powershell
python train.py --data-root E:/STUDY/DATASET/MyoPS380/Processed_data --label-order legacy --output-dir outputs/im_mseg_seed1234 --batch-size 16 --accum-steps 1 --base-lr 0.001 --seed 1234 --device cuda:0 --resume outputs/im_mseg_seed1234/last.pth
```

If pretraining was enabled initially, omit `--pretrained` on resume: the full
checkpoint retains loaded weights and initialization provenance, without needing
the original external NPZ. Reapply all other training CLI overrides. Do not
resume an old state_dict-only checkpoint or a validation run into this protocol.

`last.pth` is atomically replaced after every completed epoch. It stores model,
optimizer, scheduler, scaler, Python/NumPy/torch/CUDA and loader RNG states,
successful/skipped update counts, loss specification, source/reference hashes,
initialization, data and manifest hashes. Workers are re-created every epoch;
resume is at completed epoch boundaries, not mid-epoch. Source/config/data
changes are rejected on resume. Load only trusted full training checkpoints.

The only official result is completed_epochs=300 / zero-based epoch=299, with
training_complete=true, checkpoint_selection=last_completed_epoch and a null
checkpoint_selection_metric. No train/test score chooses an epoch or seed.

## Final evaluation

```powershell
python evaluate.py --checkpoint outputs/im_mseg_seed1234/last.pth --output-dir outputs/im_mseg_seed1234/test_final --batch-size 8 --device cuda:0
```

`test.py` is an alias with the same arguments. Partial/mismatched checkpoints are
rejected before model inference. Outputs:

```text
test_final/
  test_predictions/<case>_pred.npz  # prediction: canonical uint8 HWD
  prediction_metadata.json         # checkpoint and prediction hashes
  report/metrics.json
  report/per_case.csv
```

Inference is a single forward per slice batch, bilinear image resize and logit
resize to GT grid BEFORE argmax, no TTA/ensemble/components filtering. GT is never
modified by metric calculation. Regions are normal, scar, exclusive edema,
inclusive edema/AAR and myocardial ring. Metrics are patient means; both-empty
is excluded; one-empty has Dice/IoU=0 and undefined distances, with counts reported.

Recompute from saved predictions without model inference:

```powershell
python evaluate_predictions.py --model I-MMSeg --checkpoint outputs/im_mseg_seed1234/last.pth --predictions outputs/im_mseg_seed1234/test_final/test_predictions --output-dir outputs/im_mseg_seed1234/shared_report
```

For M2-Plus, supply its completed no-val `last.pt`, the directory produced by
SCAR evaluation containing `<case>_pred.npz` AND `metrics.json`, and the original
data/list paths if needed:

```powershell
python evaluate_predictions.py --model M2-Plus --checkpoint /path/to/last.pt --predictions /path/to/scar/test_results --data-root E:/STUDY/DATASET/MyoPS380/Processed_data --list-dir D:/NCKH/SCAR/preprocessing/splits/myops380_no_val --label-order legacy --output-dir outputs/m2_plus_shared_report
```

All 76 predictions must exist with no extra/duplicate cases and the correct
shape, uint8 dtype and canonical labels. Reports use SCAR-style top-level region
summaries in metrics.json and per-case/region rows in per_case.csv, plus provenance.
Use a fresh report directory. Do not use test results to change the final recipe.

## Verification and limits

```powershell
python -m pytest -q
python scripts/smoke_benchmark.py --device cpu
python scripts/smoke_benchmark.py --data-root E:/STUDY/DATASET/MyoPS380/Processed_data --label-order legacy --device cpu
python scripts/smoke_benchmark.py --data-root E:/STUDY/DATASET/MyoPS380/Processed_data --label-order legacy --device cuda:0 --amp bf16
```

Tests cover original-loss/gradient equivalence across schedule boundaries,
augmentation parity, mapping/normalization, fixed manifests, no validation/test
loader in the train entry point, partial-batch accumulation and exact epoch-boundary
resume (workers 0 and 1), checkpoint budget guards, initializer mapping, canonical
inference, and shared metrics over 76 SYNTHETIC patients.

Local verification also read all 1,972 real TRAIN slices successfully: 128x128,
aligned normalized modalities/masks, no all-background slices. Cache fingerprint:
`f4c9885d3f6ede61f2bda5012913e554b8035a6857480b10180a316bc57582f4`.
Test files were only inventoried/hashed for the data lock; no real test masks or
images were decoded for model debugging and no real test inference was run.

The full model has 84,975,359 parameters. CPU synthetic forward/backward passed
at epoch indices 0 and 100 with finite gradients. See the smoke command for two
actual optimization steps; this is execution validation, not an accuracy result.
GPU FP32 and BF16 smoke checks each completed two optimizer updates on a real
train slice, including contrastive/fusion at epoch index 100. A separate tiny
synthetic model with a test-only loss exercised all 300 loop iterations and final
checkpoint guards; this is a control-flow check, not I-MMSeg convergence.
No full I-MMSeg 300-epoch run or segmentation benchmark score has been produced.
Physical batch 16 and a real pretrained NPZ still require validation on the intended
training hardware before freezing final runs. See AUDIT.md for the second audit.
